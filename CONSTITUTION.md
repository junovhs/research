# Project constitution

## North star

Discover unexpected, reproducible structure in public astronomical observations. Let evidence change our questions. We want findings we did not preselect, not merely a faster search for familiar objects.

## Scope

This is a one-person research project with subscription coding agents, older consumer hardware, and occasional bounded CI. It is not a laboratory bureaucracy, an autonomous cloud service, or a data center. Default additional spending is zero. The human's own computer and permitted GitHub workflows are execution environments; ChatGPT's internal Python/container is not.

## Operating commitments

1. **Run the smallest useful test.** Prefer a short experiment to another planning document. Kill weak ideas cheaply; promote strong evidence gradually. No approval ceremony for routine work inside the agreed limits.
2. **Keep room for surprise.** Reserve at least half of exploratory probe effort for data-driven, diversified or randomly sampled investigations, not just follow-ups to favorite theories. Vary representations and sampling strata; an algorithm's idea of unusual is not nature's.
3. **Separate discovery from confirmation.** Exploration may be adaptive. Confirmation uses a frozen claim and new data, with multiplicity, selection effects and dependence addressed. Looking at a holdout consumes it.
4. **Prefer honest negatives to exciting stories.** A failed test is useful. An underpowered test is inconclusive, not proof that no effect exists. An anomaly is not a discovery and a catalog non-match is not proof of novelty.
5. **Use models for judgment, code for repeated computation.** No model call per source or per statistical probe. Subscription sessions generate and review batches of work through ordinary files.
6. **Stay portable and interruptible.** Cache small datasets, checkpoint batches, respect archive limits, and stop at budgets. No hidden background processes or automatic compute escalation.
7. **Keep only useful project machinery.** No dashboard, agent swarm, scheduler service, database server or large custom training job until a measured bottleneck justifies it. Python first; Rust only for a profiled hot path.
8. **Make evidence reproducible.** Record data provenance, query, code revision, seed, tested configurations, attempted-probe counts, failures, and resource use. Brief records are sufficient; undocumented results are not.

## Success

A reproducible surprise worth further investigation; a well-supported rejection; or a measured improvement that makes the next experiment faster or more reliable. Counts of generated ideas, runs, papers downloaded, or anomalies are not scientific success.

The human owns changes to mission, money, access, recurring-resource limits, licensing, and public claims. Agents own execution within those boundaries. This document changes when experience warrants it, not on a recurring governance schedule.
